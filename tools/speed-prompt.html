Приложение без тормозов

Добавлен 2026-11-05 · автор privatekey7

Что делает

Промпт для Claude Code: агент замеряет сайт в Lighthouse, составляет план по выигрышу и чинит по одному пункту из 30: заглушки, лёгкие картинки, кэш, индексы в базе, ответы ИИ потоком и проверка на слабом телефоне.

Команды и шаги

Хочу, чтобы моё приложение не тормозило. Работай по шагам. Шаг 1, замер: прогони главные страницы через Lighthouse в мобильном режиме (npx lighthouse <адрес> --form-factor=mobile или PageSpeed Insights), сохрани отчёт и выпиши, что красное и сколько оно стоит секунд. Шаг 2, план: сопоставь отчёт со списком ниже, отсортируй по выигрышу и покажи мне план. Без моего «да» большие переделки не начинай. Шаг 3, починка: чини по одному пункту, после каждого снова замер; если стало хуже, откати. Список. Загрузка: серые заглушки вместо белого экрана; рендер на сервере или при сборке, где это возможно; JavaScript делить по страницам; сторонние скрипты (аналитика, чаты) грузить после загрузки страницы; шрифты хранить у себя, не больше двух начертаний; кэширование статики в браузере; статику раздавать через CDN; сжатие Brotli или Gzip; удалить неиспользуемые зависимости. Картинки: WebP и AVIF; размер под экран; картинки ниже первого экрана грузить только при прокрутке (loading="lazy"). Интерфейс: длинные списки рисовать кусками, только видимое (виртуализация); убрать лишние перерисовки; кнопки и лайки обновлять сразу, не дожидаясь сервера, с откатом при ошибке; поиск и автодополнение отправлять, когда человек перестал печатать; ответы ИИ выводить потоком, по словам. Сеть и API: не допускать дублирующих запросов; независимые запросы запускать параллельно; результаты отдавать постранично; таймауты на внешние API. Сервер и база: исправить запросы N+1; индексы под частые запросы; выбирать только нужные колонки; пул подключений к базе; частые данные кэшировать в Redis; медленные задачи вынести в фоновую очередь; сервер ставить рядом с базой; при нагрузке несколько копий приложения за балансировщиком. Проверка: медленные запросы бэкенда отслеживать через OpenTelemetry; скорость у реальных пользователей через мониторинг (Web Vitals); тестировать на слабом телефоне и медленном интернете (DevTools: CPU 4x, Slow 4G). В конце покажи таблицу: что сделал, замер до и после по каждой странице.

Запускай в корне проекта. Если сайт ещё не выложен, сначала подними его локально (npm run build && npm run start), Lighthouse замеряет и localhost.

Учти

Половина пунктов про сервер и базу: на статичном лендинге агент их пропустит, и это нормально. Без замера после каждой правки легко «ускорить» в минус.
